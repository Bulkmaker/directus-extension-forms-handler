Формат [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии по [SemVer](https://semver.org/lang/ru/).

> **Легенда «Безопасно обновлять»:** ✅ да (обратно совместимо) · ⚠️ с проверкой (протестировать на dev) · ❌ breaking (читать перед обновлением).

## [1.3.1] — 2026-10-05
### Fixed
- **Подпись заявки в Telegram, MAX, VK и письме.** `getFormTypeLabel` сначала смотрел
  на `type`, а сайты `type` не шлют и валидатор подставляет `contact`: любая форма
  (отклик на вакансию, акция, квиз, смета, ипотека, отзыв) подписывалась «Контактная
  форма», название формы и объекта терялось. Теперь порядок такой: `form_title`
  («Отклик на вакансию: Каменщик»), название по известному `form_key`
  (`FORM_KEY_LABELS`: call, quiz, calc, smeta, favorites, vacancy, team-booking, promo,
  mortgage, delivery, review и др.), сам незнакомый `form_key`, затем `type`.
  Неизвестный `form_key` отправку не ломает; ключи из прототипа объекта
  (`constructor`, `toString`) безопасны.

**Безопасно обновлять:** ✅ да — контракт `POST /forms/submit`, схема и env не менялись,
меняется только текст заголовка уведомления.

## [1.3.0] — 2026-09-30
### Added
- **Маршруты заявок арендаторов** (`src/routes.ts`, `src/routing.ts`): коллекция
  `form_routes` (form_key → почта / Telegram / MAX арендатора, `copy_to_owner`,
  `active`, `note`). Включается `FORMS_ROUTES_ENABLED=true`: расширение при старте
  создаёт `form_routes` (без прав для ролей — только администратор) и поле
  `delivery_status` в коллекции заявок, если их нет. Активный маршрут — заявка уходит
  арендатору (почта тем же SMTP, Telegram и MAX тем же ботом), копия нам при
  `copy_to_owner`; если арендатору не ушло ничего — заявка приходит нам. Журнал —
  `fields._delivery` и `delivery_status`.
- **Письмо о заявке v2** (`src/lead-email.ts`): адаптивная вёрстка на таблицах, 600px,
  бренд и домен, имя и телефон с кнопкой «Позвонить», детали, источник (UTM,
  устройство, время МСК), текстовая версия. Письма арендатору — всегда v2 (без ссылки
  на CMS); письма нам — v2 при `FORMS_EMAIL_TEMPLATE=lead-v2` или в копии по маршруту.
- `GET /forms/routes/max-updates` (только администратор) — кто написал MAX-боту:
  user_id и код из ссылки `?start=…`, чтобы вписать id арендатора в маршрут.
- `sendMaxNotification(..., { recipients })`, `sendTelegramNotification(..., { chatIds })`;
  MAX возвращает `errors` по получателям (без токена).

**Безопасно обновлять:** ✅ да — без `FORMS_ROUTES_ENABLED=true` маршруты не читаются и
схема не меняется; письма нам остаются в прежнем шаблоне, пока не задан
`FORMS_EMAIL_TEMPLATE=lead-v2`; контракт `POST /forms/submit` не менялся.

## [1.2.0] — 2026-09-25
### Added
- **Уведомления о заявках в MAX** (`src/max.ts`, решение владельца 25.09: заявки уходят
  в Telegram, MAX или ВКонтакте — куда удобнее клиенту). `POST /messages` Bot API MAX,
  `format: html`, то же содержимое, что в Telegram/VK: тип формы, контакты, поля,
  калькулятор, ссылка на проект/страницу, вложения ссылками. Env: `MAX_BOT_TOKEN`,
  `MAX_CHAT_IDS`, `MAX_USER_IDS`, `MAX_API_BASE` (по умолчанию `https://botapi.max.ru`).
  Без токена или получателей канал тихо пропускается. Пользовательский ввод
  экранируется как в фиксе 1.1.0; токен вырезается из всех логов; 400 → повтор
  простым текстом, 429 → одна повторная попытка.
- Флаг `max_notified` в записи заявки.
- README: переменные окружения всех каналов (Telegram, MAX, VK, почта) одной таблицей.

### Changed
- **Notify-флаги пишутся только в существующие поля.** Раньше отсутствие поля
  `vk_notified` в схеме роняло весь `updateOne` — вместе с ним терялся и
  `telegram_notified`. Теперь флаги сверяются со схемой коллекции, недостающие
  пропускаются с предупреждением в лог.
- `resolveAttachmentUrls` возвращает `id` файла (обратно совместимо).

**Безопасно обновлять:** ✅ да — MAX выключен, пока не заданы `MAX_BOT_TOKEN` и
получатели; поле `max_notified` в схеме не требуется; контракт `POST /forms/submit`
не менялся.

## [1.1.0] — 2026-09-06
### Fixed
- **HTML-инъекция в Telegram-уведомления.** `attachments[].url` уходил в `sendMessage`
  (`parse_mode: HTML`) без экранирования — анонимный `POST /forms/submit` мог вставить
  свою кликабельную ссылку в рабочую группу заявок (фишинг по сотрудникам), а кривой
  тег ронял парсер Telegram → 400 → уведомление о лиде не приходило вовсе. Теперь
  `escapeHtml(item.url)`.
- **Выход из `href="…"` через кавычку.** `escapeHtml` не трогает `"`, а `source_url` и
  `attachments[].url` приходят из тела запроса. Добавлен `escapeHtmlAttr` (кавычки →
  `&quot;`/`&#39;`), применён во всех атрибутных позициях Telegram- и email-шаблонов.
- **Схема вложений.** `attachments[].url` теперь `.max(500).url()` + только `http(s)`.
  Невалидная ссылка НЕ отклоняет заявку (лид дороже ссылки) — вложение уезжает без URL.
- **Утечка параметров антиспама клиенту.** Ответ 400 больше не содержит `details`
  антиспама («5 requests per 60s», «1s < 3s minimum») — по ним спамер калибровал обход.
  Причина пишется в серверный лог. Ошибки валидации полей формы клиенту возвращаются
  как раньше (их показывает пользователю форма).

### Changed
- **Rate-limit (in-memory) чистит истёкшие записи.** Ключи Map никогда не удалялись:
  рассылка с ротацией IP наращивала стор без потолка → OOM Directus (Redis в стеке не
  используется, `CACHE_STORE=memory`). Добавлены периодический sweep (раз в 60с, таймер
  ленивый и `unref()`-нутый — не держит процесс и не дублируется при повторной
  инициализации модуля) и жёсткий потолок в 20 000 ключей.
- **Time-check: допуск clock-skew ±5 минут** (коммит 7c70a4d от 05.09): у клиентов со
  спешащими часами форма не отправлялась. В `dist` до 1.1.0 не попадал.

### Build
- CI-сборка `dist` падала с 2026-09-05 (`npm install` → ERESOLVE vite 8 vs
  `@vitejs/plugin-vue` → `Cannot read properties of null (reading 'edgesOut')`).
  Закоммичен `package-lock.json`, workflows переведены на `npm ci` и Node 24 (npm 11).
  `dist` 1.1.0 собран локально из актуального `src` (102 теста зелёные), тег v1.1.0
  стоит на коммите с этим `dist`.

**Безопасно обновлять:** ✅ да — контракт `POST /forms/submit` для валидных заявок не
изменился. Единственное отличие ответа: при отказе антиспама пропало поле `details`
(фронт `useUniversalFormSubmit` читает его как `response.details || []`).
